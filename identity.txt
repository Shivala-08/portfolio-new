9. Deploy Forge — Interesting Technical Problem

The strongest technical detail isn’t the deployment button.

It’s sub-path hosting.

A generated site may contain:

<script src="/main.js">

But your deployment can live at:

/sites/{id}/

Therefore:

/sites/{id}/main.js

is required instead of:

/main.js

Your pipeline currently performs recursive HTML/CSS rewriting inside the build output before committing the artifacts.  

This should be a featured case study in the portfolio.

Call it:

Making arbitrary static sites work under dynamic sub-paths

That’s a much more compelling story than “I built a deployment platform.”

⸻

10. Deploy Forge — Tradeoff

Your current README documents an important architectural tradeoff:

Git commits back to the main repository provide simple persistence and version history, but each deployment can cause Vercel to redeploy the Deploy Forge platform itself, producing a documented 30–60 second propagation delay.
